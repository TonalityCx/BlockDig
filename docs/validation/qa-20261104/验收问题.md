## QA-001 顶部暂存卡不能点击

- 版本、环境：0.1.1；内置浏览器360×640，鼠标点击；隔离控制层亦复现。
- 严重程度、状态：**P2，待主程修复，阻碍按现需求完成验收**。
- 需求依据：产品需求7.2“暂存区可点击”，A05暂存交互。
- 前置状态：开始新局，倒计时结束，当前方块尚未暂存，右侧暂存卡显示横线。
- 复现步骤：点击棋盘右侧“暂存”文字下的卡片中心（360×640时约268,192）；观察暂存卡及活动方块；随后点击底部“暂存”按钮作对照。
- 预期结果：顶部卡与底部按钮均可触发同一暂存规则，当前块进入暂存，下一块成为活动块，每块只允许一次。
- 实际结果：顶部卡保持横线，未触发暂存；底部按钮正常生效。`drawGame`只为底部暂存注册button；顶部仅绘制图形和文字。扩展检查C07断言失败，未发现顶部卡的点击目标。
- 证据：[顶部卡无响应](hold-card-no-effect-0.1.1.jpg)、[底部按钮生效](hold-bottom-0.1.1.jpg)、[C07日志](extended-report.json)。种子对本问题无影响，浏览器随机种子未记录；隔离检查种子42。
- 修复后回归：点击顶部空卡和已存方块卡、一次暂存限制、换出块初始姿态、出生受阻、暂停及倒计时禁用、至少44×44 CSS像素点击范围，以及底部按钮回归。

## QA-002 三段地下区域没有背景视觉切换

- 版本、环境：0.1.1；源码核对及Node隔离绘制指令检查。**未执行深层浏览器目视验证**，不据此评价动画观感。
- 严重程度、状态：**P2，待主程修复，阻碍按现需求完成验收**。
- 需求依据：产品需求2.1三种地下区域视觉变化、6.1背景与区域提示按深度切换、8.2区域变化柔和过渡。
- 前置状态：同一视口与布局，模型深度分别为0、10、20米；检查三个区域的背景绘制。
- 复现步骤：运行本目录 `extended-checks.cjs`；C08分别设置三个深度，调用实际 `background` 方法并采集绘制矩形的参数；核对 `Game.ts` 的 `background`、`consumeEvents` 与 `refreshHud`。
- 预期结果：三个阶段使用可区分的背景/岩壁视觉，区域切换时有约定反馈，减少动态效果时仍能识别区域。
- 实际结果：三个深度的背景绘制指令完全相同，C08失败。阶段变化实现了区域名称、提示和声音；背景绘制不读取阶段，配置中的阶段颜色未用于背景。不能据“区域名称已切换”认定背景视觉变化已实现。
- 证据：[C08日志和源码哈希](extended-report.json)、[可重跑检查](extended-checks.cjs)。本检查使用种子42控制模型，比较背景时不依赖方块序列。
- 修复后回归：使用确定性回放抵达10米、20米，在浏览器分别截图，检查过渡、文字对比度、预置层位外观、暂停冻结和减少动态效果设置。无需由测试角色先修改玩法或美术源码。

## QA-003 320×568首页关卡目标被开始按钮遮挡

- 版本、环境：0.1.1；内置浏览器320×568 CSS视口，安全区域为桌面浏览器环境。
- 严重程度、状态：**P3，建议后续适配，不单独阻碍360×640及以上约定视口验收**。
- 需求依据：首页应显示“第一矿井·目标30米”；需求最小约定视口为360×640，320×568是本轮额外覆盖。
- 前置状态：进入首页；有无本机纪录均不影响目标文字与开始按钮的位置计算。
- 复现步骤：设视口320×568，打开/刷新试玩页并等首页加载；对比360×640首页。
- 预期结果：若继续支持该额外小屏，标题、副标题、关卡目标、开始按钮不重叠。
- 实际结果：320×568中目标文字所在位置被开始按钮覆盖；360×640中目标完整可见。对局20行和底部操作区在320×568仍可见，不把首页遮挡扩大为整个小屏对局不可用。
- 证据：[320×568首页](home-overlap-320x568-0.1.1.jpg)、[360×640首页](home-360x640-0.1.1.jpg)。种子不适用。
- 后续建议：按可用高度调整首页装饰或纵向间距，再检查说明页、首页纪录及各按钮；不要通过缩小触控范围解决。

本轮工作期间UI-D1已将320×568列为待整合紧凑视口，U01计划覆盖这一问题；其设计交付仍未整合，不据此把当前画面写成已修复。本问题P3是对原有360×640及以上验收基线的影响级别，与UI设计内部的实施顺序编号分开。
