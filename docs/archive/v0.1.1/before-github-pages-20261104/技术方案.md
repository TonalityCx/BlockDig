## 3 选择理由与成本

本项目是围绕持续落块、格子碰撞、多点触控和动画反馈运行的2D游戏。统一使用游戏引擎界面，能够让棋盘、按钮、弹层与动效遵循同一套坐标、输入和资源管理方式。

Cocos 同时提供 Web 与微信小游戏发布入口，为未来评估保留了方向。本轮围绕手机浏览器组织工程，保持规则独立，避免直接为尚未确定的微信功能增加实现。将来若启动微信版本，再独立构建、适配和验收。

需要接受的成本包括编辑器安装与版本管理、场景及资源文件维护，以及相对极简 Canvas 实现更高的引擎加载开销。第一版采用2D配置、图集合并和资源裁剪，关注首次加载与低端手机表现。是否达标以实际构建测量为准。

纯 TypeScript 加轻量2D渲染库也是网页方案。当前沿用已经选定的 Cocos 与 TypeScript，利用统一场景、UI和动画工作流完成本版。微信能力不作为当前实现任务。

## 4 模块边界

### 4.1 核心规则

核心规则是可独立运行的纯 TypeScript 模块，不导入 Cocos，不访问浏览器、微信接口或文件系统。输入为玩家动作、时间推进、关卡配置与可设种子的随机源；输出为游戏状态和事件。

核心模块负责：

- 10列20行棋盘和隐藏出生空间、七种方块、随机袋、预告及暂存。
- 移动、旋转、碰撞、软降、硬降、落地锁定与锁定重置上限。
- 普通行和地层行标记、清行压实、补充地层、深度和矿石结算。
- 分数、用时、阶段速度、暂停、通关与失败优先级。

深度以地层标记计算，不能根据某格的颜色或画面位置推断。渲染层只能反映规则结果，不能通过动画结束回调自行加分或重复采矿。

时间由外部显式推进，使用毫秒计时。规则层不自行创建计时器；暂停不推进逻辑时间。引擎恢复前台后清理残余输入与时间累计，避免把后台间隔补算为大量落块。

### 4.2 对局编排

使用一个薄的对局控制层协调输入、规则与表现，维护倒计时、游玩、消行演出、暂停、通关和失败等状态。消行演出期间禁止对下一块输入，表现事件只消费一次；矿石飞行、背景过渡等次要动画可以独立播放。

这一层负责解决需求中“清行短暂停顿”和“次要动效不阻塞操作”的关系，不在不同按钮或特效脚本内各自判断游戏是否结束。

### 4.3 画面与交互

画面使用 Cocos 组件展示棋盘和UI。落定格子与活动方块分开管理，优先复用节点，避免每帧销毁并重建棋盘。方块动画的位置变化不改变规则坐标。

像素素材采用一致的采样方式，关键元素保持清晰；中文文字使用易读字体。优先关闭与本项目无关的3D、物理和骨骼动画功能，实际裁剪以构建验证为准。方块碰撞使用格子运算，不引入刚体物理。

触控区将每根手指与对应按钮绑定，管理按下、松开、滑出和取消事件。移动重复由统一输入控制器驱动，硬降一次按下只触发一次，切后台和暂停时全部清除按住状态。

键盘Esc优先处理二次确认：存在重新开始或返回首页确认时，仅关闭确认、返回暂停菜单，保持规则暂停与现有倒计时；没有确认时才切换暂停或执行继续倒计时。此分支位于界面编排层，不改变核心模型、锁定计时或地层结算。

### 4.4 配置与平台服务

关卡以 JSON 保存30行地形、矿石、区域归属和参数。加载时校验列数、格子类型、缺口、地层总数及矿石位置；可达性与可行操作示例另外验证。

平台服务通过小接口向上提供存储、前后台通知、安全区和可选震动。浏览器或微信特有调用只允许出现在适配实现中，不进入棋盘规则和界面业务脚本。

本机纪录结构带版本号与关卡ID。存储失败不会阻断游戏，读取到异常数据时回退到默认值；第一版不设计复杂存档迁移框架。

## 5 手机网页适配

以竖屏设计尺寸为参考，棋盘保持1比2比例，根据实际可用宽高计算大小，完整显示20行。顶部状态和底部触控区按需求分配空间，主要按钮触控范围不随装饰等比例缩得过小。

安全区域、浏览器工具栏展开收起和横竖屏切换分别验证。引擎提供的安全区能力可作为基础，但 Web 端实际可用区域仍需结合浏览器环境验证；不假定一个组件自动覆盖所有工具栏行为。[SafeArea参考](https://docs.cocos.com/creator/3.8/manual/zh/ui-system/components/editor/safearea.html)。

至少验证需求中的360×640、390×844和430×932视口，并在真实 Android 与 iPhone 上检查多点触控、按住重复、硬降防连发、页面滚动抑制、音频启用和后台暂停。

逻辑计时不依赖渲染帧数。初始以60帧为渲染目标，实测后确定可接受设备范围与数字验收门槛。限制高分辨率下不必要的渲染像素、粒子数量和大面积透明叠加。

## 6 微信方向留待后续评估

本轮没有微信接入里程碑，不要求AppID、微信开发者工具、微信存储实现或微信发布包。当前只保留规则层与表现层分离，以及存储、前后台和安全区域等必要服务边界。

将来明确启动微信版本时，再评估平台身份、构建、资源组织、接口适配和真机验证。微信小游戏运行环境与浏览器不同，不能将本轮网页验收视为微信验收。[官方引擎发布说明](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-wechatgame.html)。

## 7 测试与首轮验证

核心规则测试优先覆盖会影响输赢和纪录的场景：旋转与碰撞、暂存限制、锁定上限、混合清行、补地层数量、储备耗尽、矿石只结算一次、通关优先于失败、暂停不推进时间，以及固定种子与动作序列的可复现性。

Web 端完成页面流程、尺寸适配和操作冒烟检查；若使用浏览器自动化，按游戏可观测状态与画面验证，不假定 Canvas 内部存在可直接查询的HTML按钮。手机浏览器多点触控手感必须通过真机确认。

首轮技术验证的交付物为：

- 可在手机浏览器打开的最小棋盘，左右移动、旋转、硬降和暂停可用。
- 可从本地局域网在手机浏览器访问的 Web Mobile 构建，记录手机访问和验证步骤。
- 纯规则模块测试能够独立执行，不导入引擎运行时。
- 三类视口中按钮可点击、棋盘完整可见，切后台后不补算下落。
- 记录编辑器版本、依赖锁文件、初始包体与首屏加载测量结果。

这一阶段通过后，再完成挖掘关卡、矿石、结算和像素美术。本轮仅以手机网页版作为技术验证和产品验收目标。

## 0.1.0 交付时的补充

正式试玩构建关闭源码映射，通过settings/v2/packages/engine.json记录实际模块裁剪配置，保留2D、UI、图形、遮罩与音频等必要模块；没有物理或骨骼动画产物。动态消行使用裁剪区域保证方块不画出棋盘，矿石粒子与补地层平移只影响表现。

触控使用独立手指状态；键盘使用Cocos input事件。可迭代对象显式通过Array.from转换，避免Cocos宽松编译下数组展开对迭代器的兼容问题。

预览服务使用4173端口，避免与编辑器默认预览冲突。桌面通过同源竖屏容器试玩，手机直接运行完整游戏。没有远程部署、Git初始化或推送。

## UI-D1表现层交接（2026年11月4日，待整合）

详见[手机界面与素材](手机界面与素材.md)。目标在现有Graphics、Label、Mask、程序音效体系内实现；不改变core规则和地形，不新增网络服务。尺寸以实际CSS视口与四边安全区换算，布局按可用高度分档；先校验完整棋盘与按钮边界，再创建节点，空间不足时暂停提示。视口变化立即清理输入，120ms延后重排不能延后释放。

暂存卡片增加独立命中节点，底部入口与卡片共同读取model.canHold及游玩/消行/暂停/倒计时状态，不能只给图形盖暗色。多指按动作聚合，避免同向双触点产生双倍重复；瞬时动作以新按下触发，弹层切换消费旧触点。输入语义和跨消行行为见界面规格第5节。保留0.1.1的Esc取消确认优先级。

动画只消费模型事件，计数不等待飞行；粒子预算包含采矿图标。静音停止当前音源，声音加载失败不阻断关卡；设备字体不新增字体包。以上为设计要求，不代表本轮已修改Game.ts。主程整合后运行相关规则测试、TypeScript、Web Mobile构建与浏览器QA，物理设备验收单独记录。
